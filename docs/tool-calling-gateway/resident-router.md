# Resident router (:4813) — consumer guide

The resident mixed local/subscription-Claude gateway shipped by `plans/resident-router-ai-gateway.md` (build context `router/gateway/` since the 2026-10-18 cutover, fleet wiring in `fleet-tools/fleet/compose.fleet.yml` + `fleet/SERVICES.md`). Engine since 2026-10-18: the owned Rust gateway (`router/gateway/`, static `inference-router` binary, plan `plans/router-rust-gateway.md`; per-behaviour contract in `router/AGENTS.md`). It does no protocol conversion, and the local leg uses llama-server's native `/v1/messages`. History: it replaced `@the-next-ai/ai-gateway` 1.0.18, pinned at `782cd51` with a vendored patch series whose numbers survive as the behaviour names: 0001 omits `x-api-key` for the passthrough OAuth bearer (the sole defect that blocked subscription passthrough, `oauth-passthrough-probe.md`), 0002 adds the local-leg prefill/idle-gap ping keepalive, 0003 relays upstream error bodies byte-verbatim to Anthropic-protocol clients, 0004 adds the `/v1/messages/count_tokens` route (`plans/router-prefill-keepalive-and-protocol-gaps.md`), 0005 is a dependency-only lockfile bump, 0006 adds the per-request telemetry jsonl sink (`router-telemetry-baseline.md`, `plans/router-observability-and-tool-search-conformance.md`), and 0007 maps the harness's per-request reasoning effort onto the local leg's `chat_template_kwargs` (`plans/router-effort-mapping-claude-local.md`; see "Consumer profiles"). Evidence records this doc builds on: `routing-decision.md` (arm selection, qwen38 conversion fix), `oauth-passthrough-probe.md` (OAUTH-PROBE-OK / AUTH-COEXIST-OK).

One loopback port, two Anthropic-protocol legs behind one client-auth boundary:

- **Local leg** — `claude-local/*` → `inference-engine-llama` over the compose network (`:4806` internal). This is the leg that makes `qwen38-27b-iq3s` usable under Claude Code (the gateway's local-leg system merge folds the mid-conversation system message the Qwen3.8 template 500s on; before 2026-10-18 the Node engine's Anthropic→OpenAI conversion did).
- **Hosted leg** — pure OAuth passthrough to `api.anthropic.com` for **subscription Claude**. Claude Code owns the OAuth lifecycle (saved claude.ai login); the gateway preserves the bearer + `anthropic-beta` on this leg and strips them on the local leg (provider `apikey` presence/absence is the switch — see `router/AGENTS.md`).
- **OpenRouter tee** (added 2026-08-25, `openrouter-spike.md`) — `openrouter/<or-model-id>` routes via OR's OpenAI-compat endpoint through the same conversion leg as claude-local (keepalive-covered); `or-anthropic/<or-model-id>` routes via OR's native Anthropic-protocol `/api/v1/messages` (higher fidelity: OR cost fields in `usage`, native SSE; requires the client to send *some* bearer — local-mode `ANTHROPIC_AUTH_TOKEN` qualifies; the `or-anthropic/…` ids are also the picker-visible ones under model discovery). Credential is the operator's OpenRouter key via `apiKeyEnv` — never the caller's. `count_tokens` 404s on OR models (OR doesn't serve it).
- **Codex sidecar leg** (added 2026-09-11, `codex-sidecar.md`) — `codex-a/<id>` and `codex-b/<id>` route to a **host** process (`sidecar/`, `systemd --user codex-sidecar`, `:4877`) that speaks Anthropic Messages on the front and `codex app-server` JSON-RPC on the back, putting the user's Luna / Sol / Astra subscription models under Claude Code's own tools and permission model. Plain `type:"anthropic"` providers with no engine change and no new patch: the provider `name` is the model-id prefix the engine strips. The container cannot reach a host `127.0.0.1` socket, so the sidecar also binds docker0 `172.17.0.1` and the router service carries `extra_hosts: ["host.docker.internal:host-gateway"]`. Credential is a shared bridge key via `apiKeyEnv: CODEX_SIDECAR_KEY` — never the caller's bearer — and that key, not the bind address, is the authorization boundary. Effort is the harness's own control on a bare id, resolved per turn by the sidecar (an explicit `-low|-medium|-high` suffix still wins) — see "Consumer profiles". Gateway model **discovery** never surfaces these ids (same `claude`/`anthropic` substring filter), so they reach the picker as generated `modelPicker` rows and stay selectable by `ANTHROPIC_MODEL`/`ANTHROPIC_DEFAULT_*_MODEL` for headless runs. Smoke: `smoke-router.sh … --codex` (check 8, metered). End-to-end fixture verification is **complete** — six metered `claude -p` fixture runs, six green gates, across three models and both personas including two concurrent same-prompt sessions, with zero execution-boundary and zero config-verification failures; see `codex-sidecar.md` "Measured".

Client auth: static key on the **`x-gateway-key`** header (`INFERENCE_ROUTER_GATEWAY_KEY` in fleet-tools `.env`, gitignored). The `authorization` bearer is an accepted fallback auth candidate in the engine's lookup, which is what makes local mode's `ANTHROPIC_AUTH_TOKEN` form work.

## Consumer profiles

**Subscription mode** (Claude Code on your claude.ai login, routed through the gateway):

```bash
ANTHROPIC_BASE_URL=http://127.0.0.1:4813
ANTHROPIC_CUSTOM_HEADERS="x-gateway-key: <INFERENCE_ROUTER_GATEWAY_KEY value>"
# NEVER set ANTHROPIC_AUTH_TOKEN or ANTHROPIC_API_KEY in this mode — either one
# replaces the saved-login OAuth bearer and breaks or re-bills the session.
```

Claude Code keeps its saved login when only `ANTHROPIC_BASE_URL` is set; the gateway passes the OAuth bearer through untouched. Requests use the **bare** model ids (`claude-sonnet-5`, …) exactly as Claude Code sends them — a bare id auto-routes to the `anthropic` provider (verified in `resolveTargetProviders`; the `anthropic/` prefix appears only in the `/v1/models` listing).

**Local mode** (Claude Code fully on local models):

```bash
ANTHROPIC_BASE_URL=http://127.0.0.1:4813
ANTHROPIC_AUTH_TOKEN=<INFERENCE_ROUTER_GATEWAY_KEY value>
ANTHROPIC_MODEL=claude-local/qwen38-27b-iq3s
ANTHROPIC_DEFAULT_HAIKU_MODEL=claude-local/nemotron-4b
```

The `claude-local/` prefix **is required** on request ids — it is what selects the local provider over the default hosted leg. Keep small models in the haiku slot only (the WP-4 positional-derail finding, `routing-decision.md`).

**Reasoning effort on the local leg is a request field again, not the model id** (rewritten 2026-09-12, `plans/router-effort-mapping-claude-local.md`, patch `0007` — this supersedes the per-id rule `plans/local-leg-claude-code-serving-fit.md` WP-2 shipped earlier the same day, and the WP-1 spike finding behind it). Claude Code puts its own effort control on the wire — `output_config.effort` on main turns, `thinking:{"type":"disabled"}` on the side calls (titles, classifiers, summaries) — and the Anthropic→OpenAI conversion leg now reads it and merges the mapped kwargs into the upstream body's `chat_template_kwargs`. **No model-id rewrite, no model swap, no reload.** The map is configuration, per model: the additive `effortKwargs` key on the `claude-local` provider in `gateway.config.json`, keyed today only for `qwen38-27b-iq3s` — `qwen36-a3b` and `nemotron-4b` have no map, so their bodies pass through byte-unchanged, as do the hosted, codex, `or-anthropic/*` and `openrouter/*` targets.

| harness sends | level | merged into `chat_template_kwargs` |
| --- | --- | --- |
| `thinking.type: "disabled"` | `disabled` | `{"enable_thinking": false}` |
| `output_config.effort: "low"` | `low` | `{"reasoning_effort": "low"}` |
| `output_config.effort: "medium"` | `medium` | `{"reasoning_effort": "medium"}` |
| `output_config.effort: "high"` or `"max"` | `high` | `{"reasoning_effort": "xhigh"}` |
| `thinking.type: "enabled"` with numeric `budget_tokens` | `< 2048` low, `< 8192` medium, else high | as above (unit-tested; Claude Code 2.1.270 does not send this shape on this leg) |
| `thinking.type: "adaptive"`, field absent, or an unrecognised value | none | body unchanged — the map never 400s a request that would have worked without it |

Keys already on the body win the merge, and a provider `extraBody` still wins over both. The values are Qwen3.8-template vocabulary: `reasoning_effort` accepts `xhigh` (the template default) / `medium` / `low` and 500s on anything else — `none` is rejected with `Jinja Exception: Unexpected reasoning effort none`, which is why "off" is expressed as `enable_thinking:false` instead. A model whose template speaks a different vocabulary needs a different value under `effortKwargs`, not code.

**More effort is not monotonically more tokens on this template** — measured, and the reason the token-delta gate lives in one pinned test rather than in the smoke (`fleet-tools/runs/dispatch/router-effort-mapping-claude-local-wp-2-report.md`). Deterministic low-vs-medium probes through the patched router: three-switch riddle 594 → 557, divisor-count combinatorics 3229 → 1673, incline-friction physics 1378 → 890 (three of five prompts came out *shorter* at medium), against the four-friends constraint puzzle at `max_tokens 12000`, 2965 → 7919 (2.67×). The separating property is whether the prompt is a deduction the model must actually walk; on one it can answer from memory, `medium`'s template wording is terser than `low`'s. `high`→`xhigh` is gated on acceptance only (it is the template default; n=2 could not separate it from no kwargs). `router/test/conditional/effort-ladder.test.mjs` pins that puzzle and its `max_tokens` for exactly this reason — do not swap the prompt without re-measuring. The smoke's effort check is the deterministic one instead: `thinking:{"type":"disabled"}` must return a response with no `thinking` content block.

**The four suffixed ids remain valid, resolvable ids — as the server-enforced hard cap, not as picker rows.** They are unchanged llama-swap entries backed by the *same* `Qwen3.8-27B-UD-IQ3_S.gguf` at the same context and KV type, differing only in llama-server's reasoning flags, and a caller that wants a ceiling the **server** enforces (rather than a template hint the model may ignore) asks for the id by name. Their `consumers` tag in `gateway.config.json` is now `["router"]` — router-internal, meaning no Claude Code picker row and no Open WebUI row — so `/model` shows one Qwen3.8 row again and effort is chosen with the harness's own control.

| model id | flags | reasoning | picker row |
| --- | --- | --- | --- |
| `claude-local/qwen38-27b-iq3s` | `--reasoning-budget 8192` | the default; trace capped by the runaway-output backstop, and the only id carrying an `effortKwargs` map | **yes** — the one Qwen3.8 row |
| `claude-local/qwen38-27b-iq3s-off` | `--reasoning off` | no reasoning trace at all | no (`["router"]`) |
| `claude-local/qwen38-27b-iq3s-low` | `--reasoning-budget 1024` | short bounded trace | no (`["router"]`) |
| `claude-local/qwen38-27b-iq3s-medium` | `--reasoning-budget 4096` | medium bounded trace | no (`["router"]`) |
| `claude-local/qwen38-27b-iq3s-high` | `--reasoning-budget -1` | unrestricted — the pre-backstop behaviour | no (`["router"]`) |

Asking for one of the four still **swaps the resident model** (the five entries share one exclusive llama-swap group, and only one 11.21 GiB model fits on this card): expect one reload on the first request after such a switch — a cost now paid only by a caller that deliberately wants a hard cap, never by the harness changing effort. The backstop exists because an unbounded reasoning run on this model reached 22,159 output tokens against Claude Code's own 32,000-token client ceiling and killed the session; the `8192` value is gated by a baseline-vs-budget needle regression (`docs/test-matrix-results.md` records this cell failing three needles at `--reasoning-budget 128`, so a bounded budget is never assumed safe) and it still caps every mapped level from above. Adding an effort **id** needs both a llama-swap entry in `llama/config.yaml` and a line in `gateway.config.json`'s `claude-local.models[]` — an id with only one of the two 400s at `model_resolution`; adding a mapped effort **level**, or a whole new mapped model, needs neither: it is one more key under `effortKwargs` and a router restart. Per-entry capability blocks (`reasoning: "none" | "budgeted" | "request-controllable"`) follow `docs/model-capabilities.md`.

**Roster mode** (the fleet's default interactive profile: OAuth login, router base URL, the whole roster in the `/model` picker):

```bash
ANTHROPIC_BASE_URL=http://127.0.0.1:4813
ANTHROPIC_CUSTOM_HEADERS="x-gateway-key: <INFERENCE_ROUTER_GATEWAY_KEY value>"
ENABLE_TOOL_SEARCH=true                 # a custom base URL auto-disables tool search
CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1    # no background title call behind the router
# Still NEVER ANTHROPIC_AUTH_TOKEN or ANTHROPIC_API_KEY — OAuth stays the credential.
```

Those four keys live in the `env` block of `~/.claude/settings.json`, so every interactive and FleetView-launched session rides the router — and so does every subagent, which inherits the parent's base URL (there is no per-agent base URL). The picker rows come from a generated `modelPicker` lineup in the same file: `node router/model-picker-lineup.mjs --write --launch-profile` writes both the `env` block and `modelPicker.options`, one labelled row per `<provider>/<model>` id in `gateway.config.json` (e.g. `GPT-5.6 Sol (codex-b)`, `Qwen3.8 Flash (or-anthropic)`, `Qwen3.8 27B (local)`). Hosted `anthropic/claude-*` ids are excluded — they duplicate the built-in rows, and the bare id is what Claude Code sends anyway — and `replaceBuiltInOptions` is left unset so the built-in subscription rows stay first. The lineup needs no discovery and hits no id validation: behind `ANTHROPIC_BASE_URL` Claude Code passes the model string through unchecked, so `codex-a/gpt-5.6-luna` is selectable by name with no rename and no sidecar change.

**Which ids become picker rows is a per-model consumer tag** (added 2026-09-12, same WP). `gateway.config.json` carries an optional, additive `consumers` annotation per provider — either a provider-level default (`"consumers": ["openwebui"]`) or a per-model map (`"consumers": {"nemotron-4b": ["openwebui"], "qwen38-27b-iq3s": ["cc"]}`) — and the generator emits a row only for ids tagged `cc` **or left untagged**. Absent means every consumer, so an untagged provider behaves exactly as it did before the tag existed and the annotation can be rolled out one provider at a time. Today `claude-local/nemotron-4b` is tagged `openwebui` (the haiku-slot model, not a thing to pick in Claude Code). **The OR legs are Claude Code's now** (user decision 2026-09-14): `or-anthropic` carries `z-ai/glm-5.3-flash` and `qwen/qwen3.8-flash`, both `["cc"]` and both picker rows, on the **native** Anthropic leg for native SSE and OR's own `cost`/`provider` usage fields; the `openrouter` conversion leg keeps `qwen/qwen3.8-flash` tagged `router` (resolvable for protocol A/B, no row, and never an empty `models[]` — a wildcard on a credentialed provider). `z-ai/glm-5.2:free` and `z-ai/glm-5.3` were retired the same day — see the TOMBSTONE in `router/AGENTS.md`; the earlier `openwebui` tag on these providers was never real consumption, since OpenWebUI points at `inference-engine-llama:4806` and cannot reach a gateway-only id. Note `count_tokens` 404s on every OR id (`openrouter-spike.md` finding 5); the four `claude-local/qwen38-27b-iq3s-{off,low,medium,high}` hard-cap ids are tagged `router`, a tag that is neither `cc` nor `openwebui` and therefore means router-internal — no row anywhere (`plans/router-effort-mapping-claude-local.md` WP-3, once effort became a request field); the 12 suffixed codex effort ids (`gpt-5.6-luna-{medium,high}`, `gpt-5.6-sol-{low,high}`, `gpt-6-astra-{low,high}` on each persona) are tagged `router` for the same reason (see the next paragraph); and the remaining qwen and codex ids are tagged `cc` — 10 rows instead of the 28 every non-hosted id would produce. The key is unknown to the gateway engine and ignored by it: verified by running the shipped router image against the tagged config on a throwaway port, where `GET /v1/models` still listed every id with no config error in the logs. `--check` compares against the same filtered list, so tagging a provider is a normal regenerate-and-check change.

**Effort on the codex leg is the harness's control too** (rewritten 2026-09-13, `plans/codex-leg-effort-and-auditor-unpinning.md`). Pick a **bare** codex id (`codex-b/gpt-5.6-sol`) and set the level the ordinary way — `/model`'s effort control, `claude --effort <level>`, an agent definition's frontmatter `effort:`, or a `modelSettings.effortLevel` default in `~/.claude/settings.json`. It rides the wire as `output_config.effort` and the sidecar resolves it **per turn** on the existing codex thread (`max`/`xhigh` → `high`; a change costs one prefix-cache miss, never a new thread). The `-low`/`-medium`/`-high` ids remain valid, resolvable ids and **win over the request field** — explicit beats implicit — but they are tagged `["router"]` in `gateway.config.json`, so they are not picker rows: `/model` shows one row per family per persona (six codex rows, labelled with the proper model name — the family default that applies when a request carries no effort at all is in the row description, e.g. `GPT-5.6 Sol (codex-b)`). Full precedence rule and the `effortSource` log field: `codex-sidecar.md` "Effort precedence".

The last two are corrections for what a custom `ANTHROPIC_BASE_URL` changes underneath Claude Code. Setting a base URL **auto-disables tool search**, so every tool schema loads up front instead of deferring — roughly 10k tokens of extra assembly in every session — and `ENABLE_TOOL_SEARCH=true` overrides that. `CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1` suppresses the background terminal-title model call, which behind a custom base URL is not guaranteed to honour the haiku alias (anthropics/claude-code#92050, closed as not planned) and can therefore escape to the hosted API. Both are generated, so a hand-edit of either drifts on the next `--write --launch-profile`.

`node router/model-picker-lineup.mjs --check` is the sync gate (exit 1 when `gateway.config.json` and the settings file disagree; same shape as the fleet's `design:verify`) — re-run `--write --launch-profile` after any provider or model-id change. The generator owns `modelPicker.options` wholesale and, under `--launch-profile`, those four `env` keys; it touches nothing else, refuses a settings file that is not canonical 2-space JSON, and never writes `ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_API_KEY`. That refusal has an opt-in override: `--write --canonicalize` reformats the file to the canonical serialisation first and then applies its edits (semantic content, key order and unrelated keys unchanged), which is what the refusal message now points at — before it existed, a hand-edited settings file had to be round-tripped through `JSON.parse`/`stringify` by hand. `--canonicalize` is only meaningful with `--write` and is rejected with `--check`, which never rewrites anything; on an already-canonical file it is byte-for-byte identical to plain `--write`.

**Gateway model discovery is the non-OAuth alternative to Roster mode, not a companion to it.** `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` merges the gateway's `/v1/models` list into the picker, but it filters ids on `/(claude|anthropic)/i` (10 of the router's 30 ids survive today) and it **never runs in an OAuth session**: measured 2026-09-12 on Claude Code 2.1.269 (`claude -p --debug` through `:4813`), the debug log says `[gatewayDiscovery] skipped: no credential (ANTHROPIC_AUTH_TOKEN, apiKeyHelper, or API key)`. A credential supplied only through `ANTHROPIC_CUSTOM_HEADERS` also skips — the header is not a credential as far as discovery is concerned. Discovery is therefore a Local-mode feature (the gateway key is `ANTHROPIC_AUTH_TOKEN` there, and the saved login is already replaced); Subscription and Roster mode keep the OAuth bearer and use the generated lineup instead. The flag is not set on this fleet.

**Escape hatch.** Because the `env` block is always on, a down router breaks every session: launch `env -u ANTHROPIC_BASE_URL -u ANTHROPIC_CUSTOM_HEADERS claude` to fall back to the direct hosted path until the container is back.

Containment rules for agent fixtures (deny-rule profile, disposable fixture dirs) are unchanged from WP-4 — see `docs/claude-code-local-profile.md`; note its correction that only `Edit(path)` deny rules cover file-editing tools.

## Protocol coverage (closed by `plans/router-prefill-keepalive-and-protocol-gaps.md`, 2026-08-25)

Three of the four launch limitations are now shipped behavior; one accepted gap remains:

- **Prefill/idle keepalive (patch 0002, shipped)**: whenever ≥15 s pass with no frame on a local-leg streamed response — including before `message_start`, i.e. the whole prefill window — the gateway emits an `event: ping` frame, defusing the WP-4 **300 s silent-abort** condition at extreme local context. Pre-`message_start` ping tolerance was measured on Claude Code **2.1.243** (spike record in the plan doc), not assumed from the protocol reference; re-verify on a major harness upgrade. Live-verified on `:4813` (ping 8.7 s before `message_start` on a cold-model 22k-token prompt, intact completion).
- **Upstream error-body passthrough (patch 0003, shipped)**: on the final target attempt for an Anthropic-protocol client, a non-empty upstream error body is relayed byte-verbatim with the upstream status instead of the engine's `All target providers failed.` envelope — restoring Claude Code's documented fallback-on-upstream-error behavior. Other source protocols, non-final attempts, and empty bodies keep the envelope.
- **`/v1/messages/count_tokens` (patch 0004, shipped)**: proxied on both legs behind the same auth/idempotency prehandlers, with the messages path's own ordered model resolution. Live-verified on the local leg (llama.cpp serves it natively) and the hosted leg (200 through the OAuth passthrough, 2026-08-25).
- **Deferred tool search (`ENABLE_TOOL_SEARCH`, conformance-gated 2026-09-12)**: Claude Code's deferred-tool path survives the router on all three legs. Request 1 carries 12 tools — a fully-schema'd `ToolSearch`, exactly one `defer_loading: true` `DeferredToolPlaceholder`, and the always-on tools — with the deferred tools **absent from `tools`** and their names advertised in prose, in a `role:"system"` message interleaved in `messages[]` (hosted leg: inside the user turn). Discovery grows the array by exactly one fully-schema'd entry that **retains** `defer_loading: true`. Measured saving, within-leg and request-1 `system`+`tools` only: hosted 29,159 → 17,745 (tool block 2.0×), local 15,394 → 8,238, codex 14,549 → 7,875. **Cross-leg token comparison is invalid** — each leg has a different eager catalogue and a different tokenizer. Gates: `router/test/tool-search-conformance.test.mjs` and `router/smoke-tool-search.sh` (see `router/AGENTS.md` "Gates"); full measured record in `tool-search-conformance-spike.md`. The codex leg needed a sidecar fix to get there — see `codex-sidecar.md` "Deferred tool advertisement".
- **Accepted gap (unchanged)**: `?beta=true` query forwarding and open-list header forwarding are absent; both measured harmless for both legs (probe doc).

## Operations

- Config (`router/gateway.config.json`) is bind-mounted read-only; a config change needs `hc restart inference-engine-router`, then `router/smoke-router.sh http://127.0.0.1:4813 <key>` green.
- **A new Claude model id** (new release, or a legacy id an active `/model` selection sends) needs a `models` line in the `anthropic` provider + restart — the hosted list is enumerated explicitly because an empty (wildcard) list would also empty the `/v1/models` listing that model discovery depends on.
- **Never set `ANTHROPIC_API_KEY` in the service environment** — a managed key would silently hijack every subscription request onto API-key billing (`router/AGENTS.md`, compose comment block).
- An image rebuild or restart is never complete on a green healthcheck: run the smoke script (repo-wide quirk — probe by response body).
- **Per-request telemetry** (patch 0006): one jsonl line per proxied request in `~/.local/state/inference-router/logs/` on the host (`/var/log/inference-router` in the container, a rw bind mount), file `router-YYYY-MM-DD.N.jsonl` — rotated by UTC day and at `ROUTER_TELEMETRY_MAX_BYTES` (16 MiB), pruned to `ROUTER_TELEMETRY_KEEP_FILES` (14) files. `kind:"request"` is the terminal record (leg, models, session id, subagent flag, status, TTFT, wall, usage, llama `upstreamTimings`, stop reason, error stage); `kind:"progress"` lines are the in-flight view, at most one per second per request. No bodies, no prompts, no headers, no credentials — ever.
  - The service runs as `user: "1001:1001"` so those files are dulrich-owned. **Create the host directory with owner/mode before `docker compose up`** — a missing path does not error, it silently mounts an empty directory (repo-wide stale-mount quirk), and the sink then disables itself with one warning rather than failing requests.
  - Tail it: `tail -f ~/.local/state/inference-router/logs/router-$(date -u +%F).0.jsonl`; live turns only: `… | grep '"kind":"progress"'`; one session's turns: `grep '"sessionId":"<uuid>"' …`. A stream with no progress line for 15 s (`DEFAULT_TELEMETRY_STALE_MS`, `dashboard/apps/api/src/router/telemetryFeed.ts`) is **stale** — that verdict belongs to the reader, never to the writer.
  - Turning it off is `ROUTER_TELEMETRY_ENABLED=false` in the service environment; the sink is the reason `GATEWAY_LOG_LEVEL` can drop from `info` (which logs up to 32 KiB of every request body) to `warn`.
  - **Per-session report**: `docs/tool-calling-gateway/scripts/router-session-report.mjs` (Node stdlib only, no deps) reads one or more sink files line by line and emits per-turn TTFT / prefill / decode plus a cold-vs-warm summary — `node docs/tool-calling-gateway/scripts/router-session-report.mjs <sink.jsonl…> --since <iso> --until <iso> --leg claude-local --md`. Because the conversion leg drops `metadata.user_id`, `sessionId` is null on every local-leg row, so a local-leg session is selected as a **time window**, not by id (`--session` is for the hosted legs). The first measured read-out — a real Claude Code 2.1.270 session on `claude-local/qwen38-27b-iq3s` — is `local-leg-session-report-2026-09-13.md`, with its 312-line sink slice committed as a fixture and gated by `scripts/router-session-report.test.mjs`.
